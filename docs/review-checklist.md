# PR 전 점검표

PR을 올리기 전에 변경한 코드의 전체 경로를 따라가며 확인해요.

## 공통

1. **외부 호출에 시간 제한이 있나요?** Gemini, 금감원 호출과 라이브러리 안에 숨은 호출까지 확인해요.
2. **실패 분류가 일관적인가요?** 사용자 입력 오류(4xx)와 외부·서버 장애(5xx)를 섞지 않아요. 예외를 삼켜서 장애가 정상처럼 보이면 안 돼요.
3. **사용자 입력 오류는 요청 검증에서 400으로 끝나나요?** 잘못된 값이 외부 호출까지 가면 안 돼요.
4. **트랜잭션 경계가 맞나요?** 쓰기 메서드에 `@Transactional`이 있고, 트랜잭션 안에서 외부 호출을 하지 않아요.
5. **상태 변화를 빠뜨리지 않았나요?** 한 행위가 바꾸는 컬럼을 ERD에서 다시 확인해요.
6. **설정과 비밀 값이 안전한가요?** 설정은 `@ConfigurationProperties`와 `@Validated`로 받고, 비밀 값은 코드와 로그에 남기지 않아요.
7. **기존 코드 방식과 맞나요?** 같은 종류의 코드를 먼저 읽고 패키지, 예외, 테스트 방식을 맞춰요.
8. **다른 사람의 코드를 깨지 않나요?** `develop`과 열린 PR에서 사용처를 확인해요.
9. **테스트가 규칙을 실제로 지키나요?** 규칙을 빼면 테스트가 실패해야 해요.
10. **알고 있는 한계를 PR에 적었나요?** 고치지 못한 부분은 "리뷰어에게"에 적어요.
11. **외부 값은 공식 문서로 확인했나요?** 길이, 형식, 오류 코드를 추측하지 않아요.
12. **동시 요청을 따져 봤나요?** 읽고 판단한 뒤 쓰는 흐름은 조건부 갱신, 낙관적 락, 유니크 제약으로 막아요.

## What If

13. **금액이 만원 정수인가요?** 소수 계산에 `double`을 쓰지 않고 반올림은 `HALF_UP`이에요.
14. **숫자를 계산 엔진만 만드나요?** AI 답변이나 프론트가 보낸 결과를 그대로 쓰지 않아요.
15. **골든 테스트가 통과하나요?** 계산을 바꿨다면 930, 70, 93%, 5.8, 1,050을 확인해요.
16. **본인 소유만 접근하나요?** 남의 상황은 404로 응답해요.
17. **저장을 다시 보내도 안전한가요?** `Idempotency-Key`와 `version` 충돌을 확인해요.
18. **로그에 민감한 내용이 없나요?** 질문 원문, AI 답변, 토큰, 이메일, 입력 금액을 남기지 않아요.
19. **금지 표현이 없나요?** "추천", "가장 좋은", "1위", "반드시", "무조건", "확실히"를 쓰지 않아요.
20. **문서를 같이 고쳤나요?** API나 DB가 바뀌면 `docs/api-spec.md`, `docs/erd.md`를 같은 PR에서 고쳐요.
